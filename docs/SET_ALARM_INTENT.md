# Обработка внешнего ACTION_SET_ALARM

## Назначение документа

Этот документ фиксирует правило обработки внешнего intent `ACTION_SET_ALARM`.

Этот intent может прийти от системного приложения, Ассистента или стороннего приложения. Поэтому его параметры нужно считать недоверенными и проверять до создания записи будильника.

## Точка входа

За обработку отвечает `SetAlarmActivity`.

Activity читает extras из intent и передаёт их в чистую функцию `SetAlarmSpec.toAlarm`.

`SetAlarmSpec` не зависит от Android API и покрывается обычными unit-тестами.

## Проверяемые параметры

Проверяются следующие значения:

```text
hour
minute
message
calendarDays
```

## Час

Час обязателен.

Если часа нет, будильник не создаётся. Приложение открывает основной экран, где пользователь может создать будильник вручную.

Допустимый диапазон:

```text
0..23
```

Если час меньше 0 или больше 23, будильник не создаётся.

## Минуты

Минуты должны быть в диапазоне:

```text
0..59
```

Если минуты меньше 0 или больше 59, будильник не создаётся.

Если minutes extra отсутствует во внешнем intent, Android-обвязка передаёт значение 0, что соответствует началу часа.

## Подпись будильника

Подпись будильника приводится к безопасному виду:

```text
пробелы в начале и конце убираются;
слишком длинная подпись обрезается до 120 символов.
```

Пустая подпись допустима.

## Дни повтора

Дни повтора приходят в формате java.util.Calendar:

```text
Calendar.SUNDAY = 1
Calendar.MONDAY = 2
...
Calendar.SATURDAY = 7
```

Известные значения переводятся в внутреннюю маску дней недели.

Неизвестные значения игнорируются.

Если после фильтрации не осталось ни одного дня, создаётся разовый будильник.

## Поведение при ошибке

Если параметры некорректны, SetAlarmSpec.toAlarm возвращает null.

В этом случае SetAlarmActivity не сохраняет будильник и открывает основной экран приложения.

## Что проверяется тестами

Unit-тесты проверяют:

```text
отсутствующий час;
некорректный час;
некорректные минуты;
разовый будильник без дней повтора;
перевод Calendar-дней в маску;
игнорирование неизвестных дней;
нормализацию подписи.
```

## Требуемое разрешение

`ACTION_SET_ALARM` адресован приложению-будильнику. Официальная документация
(`developer.android.com/reference/android/provider/AlarmClock`) требует от activity-обработчика
объявить разрешение, а значит вызывающий его должен держать. Дословно:

> Applications that wish to receive the ACTION_SET_ALARM, ACTION_SET_TIMER,
> ACTION_DISMISS_ALARM, ACTION_DISMISS_TIMER, and ACTION_SNOOZE_ALARM Intents
> should create an activity to handle the Intent that
> requires the permission, com.android.alarm.permission.SET_ALARM.

Поэтому в манифесте у `SetAlarmActivity` объявлено
`android:permission="com.android.alarm.permission.SET_ALARM"`.

`SET_ALARM` — **normal**-разрешение (не signature): его держат Ассистент и системные часы, но
запросить его может любое приложение. То есть A отсекает приложения, которые разрешение НЕ
запросили, однако **не защищает** от приложения, которое его получило.

## Защита от скрытой установки (правило A + C)

- **A (манифест):** `android:permission="com.android.alarm.permission.SET_ALARM"` — без разрешения
  система не доставит intent в `SetAlarmActivity`.
- **C (код):** после успешного создания будильник ВСЕГДА открывается список (`openList()`);
  `EXTRA_SKIP_UI` не даёт молчаливого создания. Исключений для «своих» вызовов нет: вызывающего
  нельзя достоверно определить по foreground/referrer/extra — это не доказательство UID.

Важно: показ списка ПОСЛЕ записи — это не согласие пользователя ДО записи. Сценарий явного
подтверждения перед сохранением — отдельная задача и здесь не реализован.

## Правило для будущих изменений

Новые параметры из внешнего intent нельзя напрямую записывать в AlarmEntity.

Сначала они должны пройти через чистый слой валидации, который можно проверить unit-тестами.

Запрещено добавлять путь, при котором внешний intent создаёт будильник **молча** (без показа
результата пользователю). Нельзя ослаблять `android:permission` у `SetAlarmActivity` и нельзя
вводить исключения по признаку вызывающего.

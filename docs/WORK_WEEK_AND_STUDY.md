# Рабочая неделя, учёба и чётность недели (будущие фичи)

Документ фиксирует продуктовые решения по режиму «по дням недели», согласованные с Артемием
(2026-07-12). §1 (различие понятий) и §2 («рабочая неделя») — **реализованы** фазой C
(2026-10, TC01–TC04); §3 (учёба) и §4 (чёт/нечёт неделя) — по-прежнему будущее направление.

## 1. Дни звонка ≠ рабочая неделя

Важное различение (иначе легко смешать):

- **Дни звонка** (маска будильника, чекбоксы Пн..Вс) — **нейтральны**. Будильник может звонить не по
  работе: тренировка, поэтический кружок, приём лекарств. Это набор дней конкретного будильника.
- **Рабочая неделя** — отдельное, **чёткое** понятие (пример Артемия: 4-дневка на ВАЗе — «четырёхдневка
  и всё тут»). Сколько дней в неделе рабочих и **с какого дня неделя начинается**.

Из-за этого различения попытка сделать степпер «рабочих дней», выставляющий маску звонка, была
**отклонена** — она смешивала два понятия. Ниже — как правильно.

Статус на текущий момент: требование соблюдено — «По выходным и праздникам» с фазы D
(2026-09) отдельный режим `mode = calendar`, а не полярность weekly; маска звонка в нём
не используется (расчёт — по глобальной рабочей неделе пользователя и производственному
календарю, `AlarmTimes.nextCalendarResolved`). В weekly полярности больше нет (`polarity` —
legacy-колонка). Понятие «рабочая неделя» реализовано как глобальная настройка
(фаза C, 2026-10): раздел настроек «Рабочая неделя», вход движка `globalWeek` — см. §2.

## 2. «Рабочая неделя» как понятие движка

Рабочая неделя должна быть **входом для движка**, а не косметикой:

- ядро должно понимать, **какой день рабочий, а какой выходной**, чтобы корректно работали праздники,
  переносы и полярность будильника (буди по рабочим / буди по выходным);
- сейчас «выходные» захардкожены как Сб/Вс (`ProductionCalendar`). При нестандартной неделе (6-дневка,
  4-дневка) это неверно: например, при 6-дневке суббота — рабочая, её нельзя глушить как выходной.

**Реализовано (фаза C, 2026-10, TC01–TC04):**

1. **Настройка (глобальная, раздел «Рабочая неделя» экрана настроек):** пресеты «5/2, Пн–Пт»,
   «6-дневка, Пн–Сб», «4-дневка, Пн–Чт» + «Свой набор» (дни выбираются чипами); по умолчанию —
   5/2. Хранится в device-protected хранилище (`alarm_settings_de`): значение доступно в пути
   звонка до разблокировки устройства (Direct Boot). «Начало недели» осталось отдельной
   настройкой только отображения и в эту настройку не входит.
2. **Движок:** неделя — явный вход `globalWeek` у `AlarmTimes.next`/`firesOn` и
   `PersonalDayResolver` (по умолчанию — стандартная неделя страны). Базовый статус дня
   (work/off) — из глобальной недели, поверх него производственный календарь накладывает
   праздники и переносы; переносы применяются, только если глобальная неделя равна
   стандартной неделе страны (Q4=4а). Изменение настройки перепланирует будильники
   (`AlarmListViewModel.applyWorkWeek` → `AlarmScheduler.rescheduleAll`).
3. **Маска не подменяется:** рабочая неделя не заменяет нейтральную маску звонка — маска
   остаётся единственным источником «дня звонка» (инвариант C-1).
4. **Режим «По выходным и праздникам» (calendar):** нерабочие дни считаются от недели
   пользователя — «выходные» это её инверсия плюс официальные нерабочие дни (Q5).

Открытые вопросы закрыты решениями фазы C (2026-09-25): хранение — **глобальная настройка**
(без миграции БД); форма — **пресеты** (5/2 Пн–Пт, 6-дневка Пн–Сб, 4-дневка Пн–Чт)
**+ «свой набор»** (не степпер «N дней»); «Начало недели» остаётся только отображением;
маска будильника остаётся единственным источником «дня звонка», а рабочая неделя влияет
на расчёт только через госкалендарь (праздники/переносы); режим `calendar` после C
считает нерабочие дни от недели пользователя. Полярность per-alarm с фазы D не вопрос:
REST действует только в режиме `calendar`.

## 3. Учёба — широкая аудитория

«Учебный» профиль — это НЕ только школьники. Аудитория (Артемий, 2026-07-12):

- школьники;
- студенты вузов/институтов/колледжей/училищ;
- работники на **курсах повышения квалификации**.

То есть любой, у кого есть регулярное расписание занятий. Каникулы/сессии/периоды переиспользуют
уже готовую механику периодов без звонка (`OffPeriod`), учебные дни — режим «по дням недели».
Подробнее — раздел «Учебный модуль» в памяти проекта (`roadmap-ideas`).

## 4. Чётная / нечётная неделя

У студентов (и не только) расписание часто зависит от **чётности учебной недели**: в чётную неделю
одни занятия/дни, в нечётную — другие. Значит нужны **разные расписания и разные будильники** по
чётности недели.

Наброски реализации (обдумать при проектировании):

- (a) флаг у weekly-будильника «только чётные / только нечётные / каждую неделю» + якорь отсчёта
  чётности (какая неделя сейчас чётная — по ISO-номеру недели или от заданной даты, по аналогии с
  якорем цикла смен);
- (b) свести к **2-недельному циклу по дням недели** — обобщение модели цикла: цикл длиной 14 дней,
  где чётность = позиция в 2-недельном цикле. Возможно переиспользовать модель цикла/якорь смен.

Пока не делаем — зафиксировано как требование.
